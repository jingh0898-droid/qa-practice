# BUG-001 登录失败无任何限流或锁定机制

| 字段 | 内容 |
|---|---|
| 缺陷编号 | BUG-001 |
| 缺陷标题 | 连续 5 次密码错误后仍可无限重试，第 6 次正确密码直接登录，全程无限流与锁定 |
| 发现时间 | 2026-11-13 |
| 发现人 | jingh0898-droid |
| 所属模块 | 登录 / Form Authentication |
| 严重程度 | 严重 |
| 优先级 | 高 |
| 复现频率 | 必现（10/10 次） |
| 测试环境 | Windows 11 / Microsoft Edge 157.0.4341.46 / 1536×864（显示设置为 125% 缩放）；被测地址 https://the-internet.herokuapp.com/login |
| 前置条件 | 未登录状态，已打开 /login 页面 |

## 复现步骤

1. 打开 https://the-internet.herokuapp.com/login
2. 用户名输入 `tomsmith`，密码输入 `wrong`，点击 Login
3. 页面停留在 /login，顶部提示条显示 `Your password is invalid!`
4. 重复第 2–3 步，共 5 次
5. 第 6 次输入用户名 `tomsmith`、密码 `SuperSecretPassword!`，点击 Login

## 实际结果

第 6 次登录**直接成功**：页面跳转至 /secure，顶部提示条显示 `You logged into a secure area!`，正文显示 `Logged in as tomsmith`。

前 5 次失败过程中，除提示条文案外无任何附加限制：

- 未出现图形验证码或滑块验证；
- 未出现「尝试次数过多」「账号已锁定」一类提示；
- 失败后可立即再次提交，无冷却时间；
- 页面响应速度无变化，未观察到递增延迟。

即：失败次数对该账号的登录权限没有任何影响。

## 预期结果

登录接口应对失败尝试做频率与次数限制，达到阈值后必须阻断自动化连续猜解。建议至少满足以下之一：

1. 同一账号连续失败 5 次后，后续登录必须通过图形验证码或滑块验证；
2. 同一账号连续失败 10 次后临时锁定 15 分钟，并提示解锁时间；
3. 对同一 IP 的登录请求做速率限制（如每分钟不超过 10 次），超限返回 429。

达到阈值后，即使输入正确密码，也应先通过额外验证再放行，避免「暴力尝试直到成功」这条路径仍然可用。

## 影响与理由

登录是账号体系的唯一入口，而认证过程没有任何速率或次数约束，攻击者可用脚本在短时间内穷举大量密码组合，或对已泄露的密码库做撞库，一旦命中即完全接管账号。

此外，系统对失败原因的提示过于细致（`Your username is invalid!` 与 `Your password is invalid!` 分开返回），等于向攻击者确认「该用户名存在」，可直接用于筛出有效账号，与无限重试叠加形成完整的账号爆破链路。因此在真实业务系统中，本问题应评为「严重」而非「一般」。

## 修复建议

1. 在服务端（而非仅前端）按「账号 + IP + 设备指纹」三个维度累计失败次数，计数窗口滑动（如 15 分钟内）；
2. 失败 5 次触发图形验证码，失败 10 次锁定账号 15 分钟并写入审计日志；
3. 统一失败提示为 `用户名或密码错误`，不再区分具体是哪一项，避免泄露账号是否存在；
4. 对高频登录请求的来源 IP 做限速，超限返回 429 并告警。
