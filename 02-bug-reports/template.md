# 缺陷报告模板

复制下面的模板，每条 bug 单独一篇，文件名 `BUG-序号-简短描述.md`。

---

## BUG-001 登录页密码框输入后提示文案遮挡输入框

| 字段 | 内容 |
|---|---|
| 缺陷编号 | BUG-001 |
| 缺陷标题 | 一句话说清“在哪、什么条件、出现什么现象” |
| 发现时间 | 2026-11-13 |
| 发现人 | 你的名字 |
| 所属模块 | 登录 / Form Authentication |
| 严重程度 | 致命 / 严重 / 一般 / 轻微 |
| 优先级 | 高 / 中 / 低 |
| 复现频率 | 必现 / 偶现（x/10 次） |
| 测试环境 | Windows 11 + Chrome 版本号 + 分辨率；被测地址 |
| 前置条件 | 已打开登录页、已登录或未登录等 |
| 复现步骤 | 1. …<br>2. …<br>3. … |
| 实际结果 | 客观描述看到的现象，不夹带猜测 |
| 预期结果 | 依据需求或通用规范应该是什么 |
| 附件 | 截图 / 录屏 / 控制台报错 / 请求响应 |
| 备注 | 是否能稳定复现、影响范围、是否阻塞后续测试 |

### 写作要点

1. **标题只写现象**，不要写“疑似代码逻辑错误”这类猜测。
2. **复现步骤要能被别人照着走通**，含具体输入值和点击位置。
3. **实际结果与预期结果分开写**，这是 bug 单的核心，两者不能混在一句里。
4. **必现/偶现要写清楚**，偶现的必须给复现次数和条件。
5. 截图比文字有力，尤其布局、错别字、提示文案类问题。
