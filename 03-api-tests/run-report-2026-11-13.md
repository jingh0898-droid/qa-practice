## 失败项（4 条，均为已登记缺陷）

| # | 用例 | 期望 | 实际 | 对应缺陷 |
|---|---|---|---|---|
| 1 | 12-`totalprice` 传字符串 | 400 | **200 且创建成功**（金额存为 null） | BUG-002 |
| 2 | 13-`checkin` 传 `2026-13-45` | 400 | **200 且创建成功**（日期存为 `0NaN-aN-aN`） | BUG-002 |
| 3 | 14-缺失 `firstname` | 400 | **500 Internal Server Error** | BUG-002 |
| 4 | 16-重复删除同一订单 | 404 | **405 Method Not Allowed** | BUG-001 之外的独立缺陷（状态码语义错） |

## 结论

1. **主流程可用**：认证、增删改查链路全部符合文档约定，接口本身能跑通。
2. **入参校验缺失**：非法类型与非法日期不但没被拒绝，还被写入库并返回成功——数据污染风险，对应 BUG-002。
3. **错误码表达不规范**：参数缺失与“资源不存在”均未使用正确语义的状态码，客户端无法据此判断原因。
4. **4 条失败断言的价值**：它们把缺陷变成了可持续回归的用例。缺陷修复后断言自动转绿，无需人工复核；若后续改动重新放开校验，这 4 条会立刻变红报警。
