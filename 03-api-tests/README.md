# 接口测试入门

接口测试不看页面，只看**请求发出去之后，服务器返回了什么**。

## 一次接口调用只有四个部分，必须逐个看

| 看什么 | 在哪看 | 看错的表现 |
|---|---|---|
| **1. 请求方法 + 地址** | Method（GET/POST/PUT/DELETE）+ URL + 查询参数 | 用 GET 去提交数据，或在 POST 里塞查询参数 |
| **2. 请求头与请求体** | Headers（`Content-Type`、`Authorization`）、Body | 传 JSON 却写 `Content-Type: text/plain`，服务端解析失败 |
| **3. 状态码** | 响应最上方 2xx/3xx/4xx/5xx | 只看“有没有返回数据”，不看 200 vs 400 |
| **4. 响应体** | Body 里的 JSON 字段 | 只确认“有返回”，没逐字段核对值 |

## 状态码记这六个就够用

| 码 | 意思 | 什么时候是预期 |
|---|---|---|
| 200 | 成功 | 正常请求返回数据 |
| 201 | 已创建 | POST 新建资源成功 |
| 400 | 请求参数有问题 | 参数缺失、格式错误时**应该**返回 400 |
| 401 / 403 | 未认证 / 无权限 | 不带 token 访问受保护接口时**应该**返回 401 |
| 404 | 资源不存在 | 查一个不存在的 id 时**应该**返回 404 |
| 500 | 服务端自己崩了 | **永远不该出现**，出现就是 bug |

关键心态：接口测试不是“能返回就算通过”，而是**该报错的必须报错**。参数不合法却返回 200，比直接报 500 更严重——因为前端会把脏数据当正常数据用。

## 练习入口（httpbin，无需注册，人人可调）

| 地址 | 用来练什么 |
|---|---|
| `https://httpbin.org/get?name=xxx` | GET + 查询参数，看 args 是否原样回显 |
| `https://httpbin.org/status/404` | 状态码，看返回是不是 404 |
| `https://httpbin.org/json` | 返回体结构，练逐字段核对 |
| `https://httpbin.org/delay/3` | 超时，练超时设置（3 秒才返回） |
| `https://httpbin.org/basic-auth/user/pass` | 认证，不带账号密码应返回 401 |

真实业务场景的完整接口练手（下一阶段）：https://restful-booker.herokuapp.com/apidoc/index.html —— 有增删改查和 token 认证，可练完整闭环。

## 写接口用例和写功能用例的区别

功能用例写「点哪里」，接口用例写「发什么请求」。字段对应：

| 功能用例字段 | 接口用例字段 |
|---|---|
| 操作步骤 | Method + URL + Headers + Body |
| 预期结果 | 状态码 + 响应体字段值 + 数据库变化 |
| 前置条件 | 已获取 token / 已存在某条数据 |
